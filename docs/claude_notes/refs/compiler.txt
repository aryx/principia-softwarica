Academic references for the compiler books
===========================================
Books: compilers/Intro.nw (Introduction + Overview/principles),
compilers/Compiler.nw, compilers/Compiler_x86.nw,
generators/CompilerGenerator_c.nw (lex and yacc)

Research only; no .nw or source files were edited. Every parenthetical
follows the BRIEF addendum ("teaching value"): it names the original
problem or machine, which idea maps to which function here, and where
Plan 9 differs.

About Thompson's design paper: compilers/docs/compiler.ms is Ken
Thompson, "Plan 9 C Compilers". Its footnote says it first appeared, in a
different form, in Proc. Summer 1990 UKUUG Conference, pp. 41-51, London.
That UKUUG version is the paper known as "A New C Compiler" (CONFIDENCE:
medium on that title; the venue and pages are verified from the
footnote). After the first full citation, the entries use the short form
"Plan 9 C Compilers", section X. The paper's own reference list contains
[Set70] Sethi-Ullman, [Aho87] Dragon book ch. 8, [Dav91] Davidson-Whalley,
[Joh79] yacc and [Szy78] Szymanski, which confirms several entries below.

Prose anchors: when the spot is prose rather than a chunk, the %ref:
lines go right BEFORE the %claude:/%tag line of the named paragraph (given
as \subsection plus the paragraph's first words).

### Intro.nw : subsection "Frontend", paragraph "The frontend transforms
source text into a structured"
(line ~536, section "Compiler principles")
Algorithm/idea: syntax-directed translation, and the lexer as a
               coroutine of the parser
Verified: in 5c, yyparse (generated from cc.y) pulls tokens by calling
          yylex, and the grammar actions build Nodes. That is Irons'
          scheme, with Conway's lexer/parser split.
CONFIDENCE: high
Proposed lines:
%ref: E. T. Irons, "A syntax directed compiler for ALGOL 60",
%  Communications of the ACM 4(1):51-55, 1961 (the first compiler
%  driven by the grammar: a semantic action is attached to each
%  syntax rule, which is exactly what every {...} action in cc.y is).
%ref: M. E. Conway, "Design of a separable transition-diagram
%  compiler", Communications of the ACM 6(7):396-408, 1963 (a COBOL
%  compiler split into a lexer and a parser that run as coroutines;
%  the paper introduced the word "coroutine". Here yyparse calls
%  yylex for each token, the same separation done with a plain
%  function call).

### Compiler.nw : <<function [[lookup]]>>
(line ~1382, section "[[Sym]]bols and [[hash]] table")
Algorithm/idea: hash table with separate chaining
Verified: lookup computes h = h*3 + c over the name, then h %= NHASH, and

          before calling strcmp. A new Sym goes at the head of the chain.
CONFIDENCE: high (Luhn 1953 as the origin of chaining is stated in
          Knuth's historical notes to 6.4)
Proposed lines:
%ref: D. E. Knuth, The Art of Computer Programming, Vol. 3: Sorting and

%  notes trace chaining to an internal IBM memo by H. P. Luhn in 1953.
%  lookup is textbook chaining with a cheap h*3+c hash and a
%  first-character test before strcmp).

### Compiler.nw : <<function [[revertdcl]]>>
(line ~1814, section "Declarations, namespaces, and scope: [[Decl]]")
Algorithm/idea: shallow binding: the Sym holds the current meaning, and
               an undo stack restores the shadowed ones
Verified: push1 copies the old type/class/offset of the Sym into a Decl
          before overwriting them. markdcl pushes a DMARK. revertdcl pops
          back to the DMARK and copies the saved fields back.
CONFIDENCE: high that the paper exists. The analogy is mine, so the
          parenthetical is worded as one.
Proposed lines:
%ref: H. G. Baker, "Shallow binding in Lisp 1.5", Communications of the
%  ACM 21(7):565-569, 1978 (Lisp's value-cell trick at run time: the
%  symbol holds the current value and a stack keeps the shadowed
%  ones. 5c does the same at compile time: [[Sym]] fields are the
%  value cell, [[dclstack]] is the stack, [[revertdcl]] the unwind.
%  Baker's own contribution, "rerooting" between environments, is
%  not needed in a compiler).

### Compiler.nw : <<[[xcom()]] set complex if addable less than 10>>
(line ~15659, section "Addressability and complexity", subsection
"Complexity: [[complex]]")
Algorithm/idea: Sethi-Ullman register-need numbering
Verified: equal child labels give label+1, unequal ones give the max,
          addressable leaves get 0, and a computed node gets at least 1.
          A function call is FNX=100, Thompson's "infinite". The prose
          names Sethi and Ullman without a \cite.
CONFIDENCE: high (the citation is confirmed in compiler.ms as [Set70])
Proposed lines:
%ref: R. Sethi and J. D. Ullman, "The generation of optimal code for
%  arithmetic expressions", Journal of the ACM 17(4):715-728, 1970
%  (for a machine with k interchangeable registers: the label is the
%  number of registers a tree needs, and evaluating the bigger-label
%  child first is optimal. 5c keeps the labelling as [[complex]] but
%  uses it only to order cgen's recursion, with FNX=100 standing in
%  for "a call clobbers everything").

### Compiler.nw : <<function [[paint1]](arm)>>
(line ~25808, section "Register allocation optimisations")
Algorithm/idea: register allocation by loop-weighted usage counts
Verified: paint1 walks one connected live region, adding CREF*r->loop
          per reference and subtracting CLOAD*r->loop per needed

### CompilerGenerator_c.nw : <<function stagen>>

### CompilerGenerator_c.nw : <<function precftn>>
(line ~6247, section "[[generators/yacc/]]", subsection "yacc.c")
Algorithm/idea: resolving shift/reduce conflicts with precedence and
               associativity
Verified: precftn compares PLEVEL(toklev[t]) with PLEVEL(levprd[r]):
          higher means shift, lower means reduce, and an equal level
          goes by ASSOC (left reduce, right shift, nonassoc error).
          Level 0 counts as a real conflict. This is the machinery
          behind cc.y's %left/%right block (Compiler.nw ~6096).
CONFIDENCE: high
Proposed lines:
%ref: A. V. Aho, S. C. Johnson, J. D. Ullman, "Deterministic parsing of
%  ambiguous grammars", Communications of the ACM 18(8):441-452, 1975
%  (shows that an ambiguous expression grammar plus precedence rules
%  gives smaller, faster parsers than the stratified unambiguous one.
%  precftn is the rule: compare [[toklev]] with [[levprd]], and use
%  %left/%right to break ties).

Side notes for the author (prose issues found while verifying; not refs):
- Compiler.nw "Register allocation optimisations" says loops "weight 5x via
  the log5 sampling". The code (loopmark: r->loop += LOOP, with LOOP=3) and
  Thompson's paper ("multiplied by three") both disagree.
- Intro.nw "Register allocation", the last %5c: sentence says "5c uses a
  simpler per-basic-block allocation", but regopt is global (a flow graph
  across basic blocks, loop-weighted, greedy).
- Intro.nw "Instruction selection" writes "(BURG, Aho and Johnson 1976)".
  BURG is Fraser-Henry-Proebsting 1992; Aho-Johnson 1976 is the DP
  optimality paper.
- Intro.nw "C's main innovation ... pointer arithmetic": BCPL already had
  address arithmetic, so C's addition is typed arithmetic that scales by
  the pointee size.
